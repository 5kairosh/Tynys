TYNYS — 7-КЕЗЕҢ: ЖҮКТЕМЕ МЕН ҚОСЫЛЫМДЫ БАСҚАРУ
Күні: 2026-10-21

Түзетілген кемшілік
Бұрын барлық келіп түскен сурет/PDF сұраулары модельдің Lock құлпында
шектеусіз күте алатын. Браузер predict/report жауабын мерзімсіз күтетін.
Бұл бірнеше қолданушы қатар кіргенде жад пен күту уақытын өсіретін.

Енді қалай жұмыс істейді
1. Бір процесс үшін 3 орын: файл жүктеп жатқан, кезекте тұрған және
   есептеліп жатқан сұраулар бірге есептеледі. Модельді бір worker орындайды.
   Бұл 3 параллель модель емес. PDF те осы ортақ кезекпен өтеді.
2. Орын толса, файл оқылмай тұрып HTTP 429 + Retry-After: 5 қайтарылады.
   Бұл қорғаныс /api/predict және /api/report екеуіне ортақ.
3. Файл жүктеу: толық body үшін 60 секунд. Бір predict body: 12 МиБ + 64 КиБ
   multipart үстемесі; report body: 128 МиБ. Әр сурет бұрынғыдай 12 МиБ,
   PDF 1–10 сурет. Бұлар процесс RSS жадының толық шегі емес.
4. Worker кезегін күту: 20 секунд; асса HTTP 503. Жұмыстың жауабын күту:
   predict 90 секунд, PDF 180 секунд; асса HTTP 504. Клиентте жалпы deadline:
   predict 190 секунд, PDF 280 секунд. Интернет/прокси бұдан ерте үзуі мүмкін.
5. TensorFlow-дың native есептеуін HTTP timeout тоқтатпайды. Timeout не
   клиенттің үзілуі кезінде де есептеу біткенше worker және admission орны
   босатылмайды. Жасырын шектеусіз executor кезегі жасалмайды.
6. Браузер қатеден кейін батырмаларды босатады, таңдалған файлды сақтайды,
   бұрын алынған нәтижені жоғалтпайды. POST автоматты қайталанбайды;
   пайдаланушы хабарламаны оқып, қайта басады. Сервер күйі автоматты
   тексеріледі: дайын болса 15 секунд, бос емес/ажыраған болса 3 секунд.
7. /api/status ішіндегі service — орындар, timeout, uptime және санақтар.
   Файл атауы, сурет, модель баллы және қолданушы ID бұл санаққа кірмейді.
   /api/health — event loop жауап беруі (200, alive); /api/ready — екі модель
   жүктелгені (200 немесе 503). Екеуі де Cache-Control: no-store береді.
   Ready — жүктеме кезінде бос орын бар деген сөз емес; service.accepting
   соны көрсетеді. Healthcheck толық модель дұрыстығының дәлелі емес.

Нақты жергілікті жүктеме сынағы
training/service_stage7/load_local.json, training/verify_service_stage7.py.
8 сұрау қатар: 3 қабылданды (200), 5-і артық жүктеме ретінде қайтарылды (429).
Ең көбі 1 worker және 3 орын. 84 health сұрауы түгел 200; p95 15,81 мс.
Қабылданған predict: 1,66–5,02 секунд, кезек күтуін қоса есептегенде.
Осы burst-тегі PDF орны толып 429 алды. Кейін PDF бөлек қайта тексерілді:
200, %PDF, 2 бет. Кейінгі predict 200; барлық орын қайта босады.
Бұл жасанды суреттермен өткізілген қысқа инженерлік сынақ. Медициналық
дәлдік, ұзақ жүктеме немесе барлық компьютердегі өнімділік кепілдігі емес.

Регрессия тексеруі
159 Python тесті өтті, 13 тәуелділік deprecation ескертуі.
33 нақты Chromium/IndexedDB тесті өтті (модель HTTP жауабы ғана stub).
Жаңа тесттер: ортақ кезек, body оқымай қайтару, queue/upload/processing timeout,
жұмыс істеп жатқан thread кезінде HTTP үзілуі, кеш туған қате, орынның қайта
босауын және браузердегі қолмен retry/PDF қатесінен қалпына келуді тексереді.
Нақты API тесттері PNG және CR DICOM 200, CT DICOM мен жалған JPG 400,
2 беттік PDF, Grad-CAM және екі модель + ensemble салыстыруын қамтиды.
Бұрынғы 1218 рентгенге fresh forward жасалды: 618 Kaggle, 200 OpenI,
400 RSNA. Архив баллынан ең үлкен айырма 2,23e-16-дан аз; санаттар мен OOD
қамтуы өзгермеді. Бұл жаңа тәуелсіз медициналық зерттеу емес.
Салмақтар, конфигурация, T, шешім шегі және OOD параметрі өзгерген жоқ.

Қалған шектеулер
Codespaces ұйқыға кетеді, квота мен туннельге тәуелді. Бұл кезең оны 24/7
хостингке айналдырмайды. Health endpoint өздігінен серверді қайта қоспайды;
сыртқы монитор/тұрақты хостинг бөлек керек. Native thread мүлде тұрып қалса,
оны қауіпсіз үзіп қайта есептеу осы нұсқада жоқ: иесі процесті қайта қосады.
Тек бір uvicorn worker қолданылады; бірнеше процесс ашылса, әрқайсысының
өз кезегі және модель көшірмесі болады. Ортақ distributed queue жоқ.
Бір ұзақ PDF қалған сұрауларды кідіртеді; 20 секундтан соң қайта басу
хабарламасы шығуы мүмкін. Аккаунттық quota, ұзақ soak/RSS сынағы және
24/7 uptime есебі орындалмаған. Клиникалық жарамдылық дәлелденбеген.

Техникалық негіз
https://docs.python.org/3.11/library/asyncio-task.html#shielding-from-cancellation
asyncio.shield HTTP күтуін underlying worker Future-ден бөледі;
орын Future шын аяқталғанда ғана босатылады.

Жарияланған нұсқа/CI дәлелі: training/service_stage7/verification.json,
deployment.json, ci.json (тек нақты орындалған соң толтырылады).

Орнатуды дәл қайталау
training/service_stage7/deployment.json ішіндегі source_revision пен manifest_sha256
бірге қолданылады. Manifest-ті дәл сол revision-нен оқу керек: кейінгі құжаттама
commit-індегі файлдар тарихи manifest snapshot-ынан өзгеше болуы мүмкін.
training/deploy_stage6.py --stage 7 --revision <source_revision> --manifest-sha <manifest_sha256>
Linux /workspaces/Tynys ішінде ғана. Басқа өзгерген файл анықталса тоқтайды,
ақаулықта backup-тан қайтарады; бұйрық credentials сұрамайды. Жоба runtime-ы
жаңартылады, контейнердегі Git HEAD жылжыды деп есептелмейді.
